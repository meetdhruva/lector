# Releasing Lector

Releases are built entirely by GitHub Actions (`.github/workflows/release.yml`).

## Cutting a release

1. Bump `version` in `[workspace.package]` of the root `Cargo.toml`, run `cargo check`
   (updates `Cargo.lock`), and add a `## <version> — <date>` section to `CHANGELOG.md`.
   Update the `<releases>` list in `packaging/linux/io.github.meetdhruva.Lector.metainfo.xml`.
2. Commit, push to `main`, wait for CI to pass.
3. Tag and push: `git tag -a v0.2.0 -m "Lector 0.2.0" && git push origin v0.2.0`.
   Alternatively run **Actions → Release → Run workflow** with the tag; it is created at the
   selected commit. Tags containing `-` (e.g. `v0.2.0-beta.1`) are published as pre-releases.

The `prepare` job fails fast if the tag does not match the workspace version.

### Dry runs

Push any `release/**` branch (e.g. `git push origin HEAD:release/v0.2.0`) to build every
artifact exactly as a release would, without publishing: the files are attached to the
workflow run as artifacts (`dist-linux-x86_64`, `dist-macos-universal`, ...). CI also runs
on `release/**` branches, so the full test suite runs on Linux, macOS and Windows first.

## What gets built

| Job | Runner | Artifacts |
|---|---|---|
| Linux x86_64 | ubuntu-22.04 (glibc 2.35) | `.deb`, `.rpm`, `.AppImage`, portable `.tar.gz` |
| Linux aarch64 | ubuntu-22.04-arm | same |
| macOS universal | macos-latest (arm64 + x86_64 cross, `lipo`) | `.dmg`, `.zip` (ad-hoc signed `Lector.app`) |
| Windows x64 | windows-latest | Inno Setup `setup.exe`, WiX `.msi`, portable `.zip` |
| Windows arm64 | windows-latest (cross-compiled) | same |

Binaries use the `dist` profile (thin LTO, one codegen unit, stripped). Every artifact
contains the licenses, `README.md`, `CHANGELOG.md` and `third-party/` notices, including
the full license texts of all Rust dependencies generated by `cargo about` (`about.toml`,
`about.hbs`). The publish job adds `SHA256SUMS.txt`.

## Packaging locally

```sh
cargo build --profile dist -p lector
cargo about generate --workspace about.hbs -o target/THIRD_PARTY_CRATES.md   # optional
scripts/package-linux.sh target/dist/lector 0.3.0 x86_64 dist        # needs dpkg-deb; rpmbuild/appimagetool optional
scripts/package-macos.sh target/dist/lector 0.3.0 aarch64 dist       # on macOS
pwsh scripts/package-windows.ps1 -Binary target\dist\lector.exe -Version 0.3.0 -Arch x64 -OutDir dist
```

## Platform integration

| | |
|---|---|
| App id | `io.github.meetdhruva.Lector` (Wayland app id / X11 class, desktop file, AppStream, macOS bundle id) |
| Icon | `assets/app-icon/lector.svg` → `png/`, `lector.ico` (7 sizes), `lector.icns` (incl. @2x) |
| Linux | desktop entry with MIME types, AppStream metainfo, hicolor icons; tarball `install.sh` / `uninstall.sh` |
| macOS | `Info.plist` with document types (folders, source files), Finder "Open With" and dock reopen handled by the app |
| Windows | icon and version info embedded in `lector.exe` (`crates/lector/build.rs`), no console window in release builds, optional PATH entry, "Open with Lector" Explorer menu, Start menu shortcut |
| Portable | a `lector-data` folder next to the executable holds all settings and state |

## Signing (not yet)

Builds are currently unsigned (macOS bundles are ad-hoc signed so they run on Apple Silicon).
Planned: Apple Developer ID signing + notarization in the macOS job (`codesign`, `notarytool`,
`stapler`), Authenticode signing of `lector.exe`, `setup.exe` and the `.msi` in the Windows job,
and GPG/minisign signatures for the Linux packages and `SHA256SUMS.txt`.
